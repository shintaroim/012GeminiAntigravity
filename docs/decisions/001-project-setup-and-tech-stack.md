# ADR 001: プロジェクト基盤の技術選定と設計方針

## 状態
承認済み (Accepted)

## 日付
2026-10-12

## コンテキスト
HON-NEoは現在Gemini Gem上で運用されているが、専用URLによる独立WebアプリとしてMVPを構築する必要がある。
利用者は40代女性を中心とする個人で、アカウント登録なしでもスムーズに対話を開始・再開できること、AIプロバイダーにロックインされないこと、元プロンプトの思想（人生編集者、1ターン1問、原文保持、断定しない、反証探索等）を完全に遵守することが求められる。

## 決定事項
1. **フレームワーク・言語:**
   - Next.js (App Router) + TypeScript を採用する。
   - スタイリングは Tailwind CSS を採用し、モバイルファーストで迅速かつ保守性の高いUIを構築する。
2. **バリデーション:**
   - Zod を採用し、APIリクエスト境界およびAI出力状態更新のスキーマ検証を厳格に行う。
3. **テストフレームワーク:**
   - Vitest を採用し、単体テスト・統合テスト・プロンプト回帰テストを高速に実行できるようにする。
4. **元プロンプトの保全:**
   - `custom-instruction-text.txt` を正本として `docs/source-prompt-v1.0.md` に配置し、改変せず参照可能とする。
   - 実行時プロンプトは `prompts/` 以下に機能別分割して管理し、正本との差分チェックリストを作成・保守する。
5. **AIプロバイダーの抽象化:**
   - `AIProvider` インターフェースを定義し、モックプロバイダー、Gemini API、OpenAI API等を環境変数 `AI_PROVIDER` で切り替え可能とする。
6. **匿名セッションとセキュリティ:**
   - 匿名セッションID（UUID）に加えて、推測不可能な再開トークン（Resume Token）を発行。
   - サーバー側ではトークンのハッシュ値のみを保持し、セッション所有権を検証する。
   - APIキーや内部状態、プロンプトをブラウザへ露出しない。

## 結果・影響
- 開発AIや開発者がプロジェクト構造を把握しやすくなる。
- プロバイダー変更や将来のDB移行（PostgreSQL / Supabase）が容易になる。
- セキュリティ・プライバシー・プロンプト思想が初期段階から保護される。
